# 06_최종.md 포맷

앞부분(전략 검토)은 양식과 무관하게 **고정**, 본문은 양식 목차를 따른다. `사업계획서실무교재.html`이 이 구조를 읽어 화면을 만든다.

## 1. 전체 구조

```markdown
# 전략 검토
## 핵심 키워드
## 전략 매트릭스
## 유지할 점 / 수정할 점
# 1. (양식 대항목)            ← 여기부터 양식 목차 순서
## 1-1. (양식 소항목)         ← 복사 단위
# 2. …
# 준비할 입증 자료
# 심사표 대조                 ← 심사표가 있을 때만
```

## 2. 전략 검토 — 고정 형식

### 핵심 키워드 (개조식)

키워드마다 한 블록. **다른 섹션과 같은 문장 규칙을 따른다** — 상위 메시지 3분할, 말머리 2분할, 입증 방안.
`01_문장구조.md` 3.6절 일반형의 `핵심 키워드` 행을 쓴다.

```markdown
## 핵심 키워드

1. (#키워드1) 무엇을 축으로 삼는가 — 정책 근거와 기업 역량을 잇는 3분할 상위 메시지
  - (정책 근거) 공고문·정책 문구 ─연결어미─ 어디에 근거하는지
  - (기업 역량) 기업정보의 어떤 자산 ─연결어미─ 어떻게 연결되는지
  - (계획서 역할) 이 키워드가 관통할 목차 ─연결어미─ 무엇을 각인시키는지
  (입증 방안: 필요 자료)
```

서술식 문단으로 쓰지 않는다. 계획서 전체가 한 문체여야 심사자가 같은 리듬으로 읽는다.

```markdown
## 핵심 키워드

**#피지컬AI** — 공고문이 지원 분야 1순위로 명시한 '제조 현장 자율화'를 정부 용어로 옮긴 축이다. 2026 제조 AI 로드맵의 "인지·판단·행동 통합" 문구와 직접 맞닿는다. 기업이 보유한 공정 이상감지 납품 실적 12건이 이 축의 선행연구가 된다.

**#돌발대응** — …

**#인접시장확장** — …
```

### 전략 매트릭스 (표)

`04_정렬.md`의 표를 그대로 옮긴다. **가로와 세로는 다른 것을 본다** — 오른쪽 열과 하단 행이 각각의 판정이다.

| 위치 | 이름 | 무엇을 보나 | 어떻게 적나 |
|---|---|---|---|
| 맨 오른쪽 열 | **가로 검토** | **MECE** — 세 항목이 겹치지 않고, 그 목차가 묻는 범위를 함께 덮는가 | `✅ MECE — 구동·추론·성과로 층이 나뉨` |
| 맨 아래 행 | **세로 검토** | **논리 흐름** — 그 키워드가 목차를 따라 어떤 논리로 이어지는가 | `✅ 무선망 단절(배경) → 실습 중단(필요성) → 단말 추론(개발내용) 으로 한 줄` |
| `N-입증전략` 행 | 전략 | 셀마다 입증 방안이 서는가 | 20자 내외 |

매트릭스의 각 셀은 **본문 상위 메시지 그대로**다. 7단계에서 그 줄을 그대로 옮기고 세부·입증만 붙인다.

**세로 검토에 판정 기호만 적지 않는다.** 관통 논리를 문장으로 써야 본문이 그대로 나온다.
논리가 약간 무리해도 일관되게 정렬되면 심사자가 기억한다 — 각각 옳은 말을 따로 적으면 아무것도 남지 않는다.

**#정렬 결과를 별도 절로 빼지 않는다.** 매트릭스가 곧 정렬표다 — 판정은 이 표의 열과 행에만 적는다.
표 밖에 "정렬 분석" 같은 절을 따로 만들면 같은 말이 두 번 나오고 수정할 때 갈라진다.

```markdown
## 전략 매트릭스

| 목차 | #키워드1 | #키워드2 | #키워드3 | 가로 검토 |
|---|---|---|---|---|
| **1. 연구개발 배경** | (한 문장) | (한 문장) | (한 문장) | ✅ 세 축이 정책→현장→기술 순으로 배치 |
| 1-입증전략 | 로드맵 문구 | MTBF 통계 | 납품 실적 | |
| **2. 목적 및 필요성** | | | | ⚠️ 키워드2가 배경과 같은 말 반복 |
| 2-입증전략 | | | | |
| **3. 연구개발 내용** | | | | ✅ |
| 3-입증전략 | | | | |
| **RFP 커버리지** | 요구 1·2 | 요구 3 | 요구 4·5 | ❌ 요구 6 미배치 |   ← 지정공모만
| **세로 검토** | ✅ 5회 반복 | ⚠️ 사업화에서 끊김 | ✅ | |
```

✅ 정렬됨 / ⚠️ 보완 / ❌ 끊김·누락.
**가로 검토**는 그 목차의 분리·계층에 대해 한 줄. **세로 검토**는 반복 횟수와 끊긴 목차 번호.
끊김·약함을 적을 때는 **목차 번호를 밝힌다**(`9번에서 끊김`, `3·4에서 약함`) — 교재가 그 번호로 이동 링크를 만든다.

### 유지할 점 / 수정할 점 (사람 검토 필수)

이 절은 **LLM이 매트릭스를 읽고 낸 판단**이다. 사실 확인이 아니다.
그래서 절 머리에 다음 한 줄을 반드시 넣는다 — 교재도 이 줄을 경고 블록으로 띄운다.

```markdown
## 유지할 점 / 수정할 점

> **아래는 LLM이 매트릭스를 읽고 낸 분석입니다. 반드시 사람이 검토하세요.**
> 공고 해석·기업 사정·심사 관행은 LLM이 모르는 부분이 있습니다.

**유지**
- 배경1→필요성1→개발내용1이 '돌발 대응력'으로 일관
**수정** (반영 완료)
- 사업화에서 #돌발대응 끊김 → 타겟 시장 셀에 "돌발 정지 손실 큰 라인" 추가
```

수정할 점은 정렬 단계에서 이미 반영한 것을 기록한다. 남은 게 있으면 `(미반영: 이유)`.

## 3. 본문 — 헤딩은 양식 항목까지만

```markdown
# 2. 연구개발 방법                 ← 양식 대항목
## 2-1. 개발 내용                  ← 양식 소항목 = 복사 단위
1. (#키워드) 상위 메시지
  ※ 책임자: …                      ← 개발내용·선행연구·사업화만
  ① 세부 개발 항목                  ← 헤딩이 아니라 블록 안 번호줄
    - (개발 대상) 단위 1 ─연결어미─ 단위 2
    - (적용 방법) 단위 1 ─연결어미─ 단위 2
  (입증 방안: …)
2. (#키워드) …
## 2-2. 검증 방법                   ← 다음 복사 단위
```

- `###` 이하 금지. 교재가 `##`을 하나의 복사 단위로 만들기 때문
- 소항목이 없는 대항목은 `#` 아래 바로 블록 — 교재가 그 `#`을 복사 단위로 만든다. 소항목 번호는 양식 표기 그대로(`## (1) …`도 됨)
- 블록 안 세부 번호는 양식 번호와 겹치면 ①②③, 안 겹치면 `1-1.`
- 양식 ①②③ 문항 → 소제목으로 두고 그 안에서 블록. 표 서식 → 칸을 채우되 칸 안에서 2분할. 양식에 표가 없으면 표를 만들지 않는다
- "서술형으로 작성" 지침 → **묻지 않고 블록 유지**, 한 줄로 알린다 (스킬 정책: 한 섹션만 서술형이면 리듬이 깨지고 입증 방안이 묻힌다). `## 핵심 키워드` 세 문단만 예외로 서술식이다

### 표준 블록

```
1. (#키워드) 구성단위 A + 구성단위 B + 구성단위 C     ← 3분할, 명사 위주, 완결형
  - (말머리) 단위 1 ─연결어미─ 단위 2                 ← 2분할, 30자 안팎, 명사형 종결
  - (말머리) …
  (입증 방안: 필요 자료의 유형)
```

`+` `─연결어미─` `{ }`는 표기용. 출력에 쓰지 않는다. 구성단위·말머리 세트는 `01_문장구조.md` 3장.

### 섹션 예 (배경)

```
1. (#경량화) 전비 향상 요구 확대에 따른 토폴로지 최적화 기반 구동부 중량 20% 절감 필요
  - (내/외부 환경) 주행거리 규제 강화 및 배터리 원가 부담에 따른 경량화 압력 증가
  - (현 상황 한계) 주조·금형 방식 가공으로 인한 부품 통합 및 중량 절감의 구조적 한계
  - (기술 개발) 적층제조(DfAM) 기반 통합 하우징 제작을 통한 기존 대비 20% 중량 절감
  (입증 방안: 주조 대비 3D 프린팅 차이 데이터, 적층제조 양산성 자료)
```

## 3.9 `[예시]` 표기 — 사실 정보가 필요한 자리

기업정보·공고문·양식에 없는 값(성명·학력·실측 수치·금액·매출·시험 성적)은 **빈칸으로 두지 않는다.**
빈칸은 무엇을 넣어야 하는지 가르쳐 주지 않고, 사용자는 그 칸을 그대로 비워 제출한다.

- 값 앞에 `` `[예시]` `` 를 붙여 형식이 보이게 채운다 — `` `[예시]` 62 ``, `` `[예시]` 김OO ``
- 표시가 없는 값은 **사실**이라는 뜻이다. 사실이 아닌데 표시를 빼면 그것이 허위 기재다
- `[예시]`가 들어간 항목은 **반드시** `# 준비할 입증 자료`에 대응 항목을 올린다. 짝이 없으면 안 된다
- 그 블록의 `(입증 방안: …)` 줄에 무엇으로 교체하는지 적는다
- 요약(양식 선두 항목) 바로 아래에 표기 규약 한 문단, `# 준비할 입증 자료` 머리에 강조 한 문단을 둔다
- `# 준비할 입증 자료` 머리에 **`[예시]`가 남아 있는 항목 목록**을 한 줄로 적는다

```markdown
> **`[예시]` 표시가 붙은 값은 형식을 보여주려고 넣은 것이다. 그대로 제출하면 안 된다.**
> 실제 자료로 교체해야 할 것은 문서 끝 `# 준비할 입증 자료`에 전부 모아 두었다.
> 표시가 없는 값은 기업정보·공고문·양식에서 그대로 가져온 사실이다.
```

배점이 걸린 자리(정량 목표·연구원 현황·사업비·매출)는 표 아래에 **왜 실제 자료가 필요한지**를
한두 줄로 덧붙인다 — "기술성 40점이 걸리는 자리라 근거 없는 숫자는 그대로 감점이 된다".

## 3.10 심사표 대조 — 없어도 비우지 않는다

**배점은 세 곳에서 찾는다. 순서가 있다.**

1. 별도 심사표 파일 (`서면 심사 평가기준.txt` 같은 것)
2. **공고문 본문의 배점표** — `scripts/find_rubric.py 공고.md`. 실제로 이쪽이 더 흔하다
3. 둘 다 없을 때만 `[기본값]` 일반 배점

①②로 찾았으면 `[기본값]` 표시를 **붙이지 않는다.** 그 표시는 "실제 공고 기준이 아님"을 뜻한다.
①②는 항목별 강·약까지 채운다. ③은 강·약 칸을 비우고 안내만 단다.

**기본 배점** — `기술성 40 · 사업성 20 · 기술개발역량 20 · 파급효과 15 · 자금집행계획 5`

```markdown
# 심사표 대조

| 배점 항목 | 배점 | 지금 강한 곳 | 지금 약한 곳 |
|---|---|---|---|
| `[기본값]` 기술성 | 40 | | |
...
공고문의 심사표를 함께 주시면 실제 배점으로 항목별 강·약을 대조해 드립니다.
```

강·약 칸은 **비운다.** 대조는 실제 심사표가 있어야 하고, 없는데 채우면 그것이 지어낸 것이다.
이 배점은 `assets/사업계획서실무교재.html`의 `DEFAULT_RUBRIC`과 같아야 한다 — `check.sh`가 대조한다.

## 3.11 교재가 읽는 계약

`06_최종.md`는 사용자가 **교재(`사업계획서실무교재.html`)에 넣어서 보는 파일**이다.
아래 토큰이 교재의 화면을 만든다. 형식이 어긋나면 그 화면이 통째로 비거나 잘못 그려진다.

| 쓰는 것 | 교재가 만드는 것 |
|---|---|
| `# 대항목` | 목차 1단, 블록 그룹 |
| `## 소항목` | 목차 2단, **복사 단위** |
| `# 전략 검토` | ② 전략 설계 |
| `## 핵심 키워드` + `1. (#키워드) …` | 키워드 카드 3장 (개조식이어야 한다) |
| `## 전략 매트릭스` — 첫 열 `목차`, 끝 열 `가로 검토`, 끝 행 `세로 검토` | **2차원 다이어그램.** 세로 ↓ 흐름, 가로 → 병렬 |
| 목차 라벨을 **번호로 시작** (`1. 기술개발 목표`) | 다이어그램에서 그 목차 본문으로 이동 |
| 세로 검토에 **목차 번호** (`9번에서 끊김`) | 그 칸을 약함(◐)으로 표시 |
| `N-입증전략` 행 | 다이어그램 슬림 행 |
| `# 준비할 입증 자료`, `# 심사표 대조` | ② 검토·유의사항 |
| `>` 인용문 | 지침 블록. **복사 대상 제외** |
| `(말머리) 값 — 근거` | 양식 표에서 옮긴 값 줄. 2분할·길이 규칙에서 빠진다 |
| `※` 로 시작하는 줄 | 약한 캡션. **복사 대상 제외** |
| `(#키워드)` | 인라인 칩 + 우측 키워드 필터 |
| `[예시]` | 검정 배지 + `[예시] 교체` 카운터 |
| `[기준]` | 규정이 정하는 값. `# 확인할 규정` 과 짝을 이룬다 |
| 본문 없이 `※` 만 있는 항목 | **첨부 서류**로 보고 입력 상자를 만들지 않는다 |
| `(입증 방안: …)` | 보조 줄 + `입증 자료` 카운터 |
| `확인 필요` | `확인 필요` 카운터 |
| `<!-- 수정됨 -->` | 9단계에서 손댈 항목 표시 |

한글 양식의 사용자 정의 영역 문자(`󰊱` 등)는 교재가 지운다. 그대로 둬도 된다.

이 계약이 깨지면 교재의 해당 화면이 비거나 잘못 그려진다. 8단계 병합 후 위 표를 한 줄씩 대조한다.

## 4. 준비할 입증 자료

본문의 `(입증 자료 필요: …)` `(준비 필요: …)`를 모아 우선순위로.

```markdown
# 준비할 입증 자료

1. 구매의향서 2~3건 — 사업화 2-1, 심사 배점 20점 직결
2. 등록특허 청구항 사본 — 선행연구 3-1
3. 설비 MTBF 통계 (자사 납품처) — 배경 1-1
```

## 5. 한글로 옮길 때

`사업계획서실무교재.html`에 `06_최종.md`를 넣고 `##` 단위로 **복사** 버튼을 눌러 한글 양식에 붙인다.
본문에는 마크다운 표가 없으므로(3.11·6장) 칸마다 옮기면 된다. `^(…)`는 위 첨자로, `**볼드**`는 배경색+굵게.
