# 단계별 진행

인터뷰(3단계) 확정 후 4~8단계는 **묻지 않고 연속 실행**한다. 각 단계 산출물은 파일로 남기되 사용자에게 보여주지 않는다. 8단계 `06_최종.md`만 전달한다.

## 1. 입력 자료

| 자료 | 없으면 |
|---|---|
| 공고문 | 키워드 근거가 없어 일반론이 된다. 가장 아쉬운 누락 |
| RFP (지정공모) | 요구 항목 커버리지를 못 본다. 지정공모는 누락이 감점 |
| 작성양식 | 목차·분량·표 칸을 모른다. 일반 양식(배경·목적·개발내용·사업화·기대효과)으로 추정 |
| 기업정보 | 입증 전략이 전부 "제안" 수준 |
| 심사표 | 배점 대조 불가. **다만 별도 파일이 없어도 공고문 본문에 표로 들어 있는 경우가 더 많다** — `find_rubric.py` 로 먼저 찾는다 |

한글 문서는 **전부 `extract_doc.py --tables`** 로 추출한다.
정부 양식은 거의 전부 표라서 표 없이는 과제 개요 같은 선두 항목이 사라지고,
**공고문의 심사표도 표 안에 있어** `--tables` 없이 뽑으면 `find_rubric.py` 가 찾지 못한다.
그러면 실제 배점이 있는데도 기본 배점으로 대조하게 된다.

**심사표는 공고문 안을 먼저 뒤진다.** 별도 파일로 오는 경우보다 공고문 본문에 표로 있는 경우가 많다.

```bash
python3 scripts/extract_doc.py <공고문> --tables -o 공고.md
python3 scripts/find_rubric.py 공고.md          # 후보가 여럿이면 --all
```

찾으면 그 배점을 `# 심사표 대조` 에 그대로 쓴다. 못 찾고 별도 파일도 없을 때만 `[기본값]` 배점표를 쓴다.

추출하면 표마다 `<!-- 표:본문칸 -->` 같은 이름표가 붙는다. **표의 3/4는 채우는 표가 아니라 글 쓰는 자리다.** 이름표를 그대로 믿고 대응한다 — `01_문장구조.md` 0장.

## 2. 작업 폴더

`init_workspace.py <폴더>`. 기존 폴더면 상태를 보고 다음 단계부터.

## 3. 셀프 인터뷰 → `01_아이디어.md`

`03_인터뷰_설계.md`. 체크리스트 9개를 채우고 확정 요약을 보여준 뒤 **"이대로 진행할까요?"** — 유일한 확인 지점. 확정되면 4~8단계를 연속 실행한다.

## 4. #이해 → `02_이해.md`

"정부는 왜 이 항목을 쓰라고 했는가"를 심사자 시선으로. **모든 목차**(행정 항목 포함, 번호 없는 과제 개요 포함)에 대해:

| 목차 | 분량 | 표 유형 | 양식 지침·작성 요령(원문 그대로) | 작성 의도 | 대응 전략 | 입증 방안 |

**표 유형** 칸에는 추출본의 이름표를 그대로 옮긴다(`본문칸`·`라벨값표`·`데이터표(4열)`…).

**양식 지침·작성 요령 칸**에는 그 항목에 붙은 지시를 **원문 그대로** 모은다. 세 군데에서 나온다.
1. `표:지침칸`의 `※` 문구
2. 항목 제목 옆 괄호나 `*` 로 붙은 안내 (`* 최대 2페이지`, `해당 사항 없으면 미기재`)
3. **표가 지시하는 항목 이름** — 성과지표 표의 열 제목, 추진일정 표의 단계 구분 같은 것.
   그 표는 "이런 것들을 이렇게 쓰라"는 **작성 요령**이다

이 칸의 지시는 본문에 옮겨 적는 내용이 아니라 **따라야 할 규칙**이다. 7단계에서 하나씩 대조한다.

입증 방안은 `01_아이디어.md`의 입증 자산 표와 `02_입증전략.md` 매핑을 대조해 채운다. 보유 = 그대로, 미보유 = `(준비 필요: OOO)`.

## 5. #구조화 → `03_구조화.md`

`04_구조화_유형별.md`. 세로=목차, 가로=키워드 3개, 목차마다 `N-입증전략` 행.
**각 셀은 본문의 상위 메시지 그대로 쓴다** — 3분할·완결형(`01_문장구조.md` 1장). 조각으로 적어 두면 7단계에서 다시 써야 한다. 행정 항목(예산·일정·장비·안전·일반현황)은 매트릭스에서만 제외. 지정공모는 맨 아래 **RFP 커버리지** 행.

## 6. #정렬 → `04_정렬.md`

1. **세로로 읽는다** — 키워드 열마다 배경→필요성→개발내용→사업화가 **어떤 논리로** 이어지는지 (스크립트로는 못 잰다)
2. **가로로 읽는다** — 목차 행마다 세 셀이 **MECE 인지**. 겹치지 않고, 그 목차가 묻는 범위를 함께 덮는지. 세로와 **다른 질문**이다
3. 판정을 매트릭스에 적는다 — `04_구조화_유형별.md` 검토 축 표
   - 맨 오른쪽 **가로 검토** 열: 목차마다 ✅/⚠️/❌ + 겹침·누락·계층 중 무엇인지
   - 맨 아래 **세로 검토** 행: 키워드마다 ✅/⚠️/❌ + **무엇으로 이어지는지**. 판정 기호만 적지 않는다.
     이어지면 관통 논리 한 줄만 쓰고, **목차를 하나씩 나열하지 않는다.**
     끊기거나 약하면 **어긋난 목차만** 번호로 짚고 이유와 봉합 방법을 쓴다
4. `[유지할 점]` `[수정할 점]` 정리 — 세로에서 나온 것과 가로에서 나온 것을 섞지 않는다.
   절 머리에 **"LLM 분석이므로 반드시 사람이 검토하세요"** 인용문을 넣는다. 이건 판단이지 사실 확인이 아니다
5. **수정할 점을 스스로 반영**해 매트릭스를 고친 뒤 저장한다. 사용자에게 묻지 않는다

이 표가 그대로 `06_최종.md`의 전략 검토가 된다.

## 7. 본문 → `05_본문/`

`01_문장구조.md`를 읽고 시작. 양식 대항목마다 한 파일(`1_기술개발목표.md`). 파일 안은 `#` 대항목 / `##` 소항목 / 그 아래 블록. `###` 이하 금지.

각 소항목: `02_이해.md`의 **표 유형**과 **양식 지침·작성 요령** 칸을 먼저 본다.

- `본문칸` → 블록만 쓴다
- `라벨값표`·`데이터표` → **그 표가 요구하는 항목을 텍스트로 쓴다.** 마크다운 표를 만들지 않는다(아래)
- 작성 요령에 적힌 분량·필수 포함 사항·미기재 조건을 하나씩 대조한다
- **동의서·서약서·증명서·등록증·신고필증처럼 첨부하는 항목은 블록을 만들지 않는다.**
  `※` 로 무엇을 준비하는지 한 줄만 적고 `# 준비할 입증 자료` 에 올린다.
  옮겨 적을 내용이 없는데 상자를 만들면 수강생이 뭔가 써야 하는 줄 안다
- **사업비·일정·인력·추진체계·컨소시엄 항목이면 `06_형식항목.md` 를 읽고 쓴다.**
  규정이 형식을 정하는 3수준이라 1·2수준처럼 쓰면 형식은 맞고 규정은 틀린다

**본문에는 마크다운 표를 만들지 않는다.** 양식의 표는 "이런 항목들을 쓰라"는 작성 요령이지
표를 그려 달라는 뜻이 아니다. 수강생이 한글 양식에 옮길 때 마크다운 표는 깨지고, 칸마다 다시 나눠야 한다.
표가 요구하는 항목은 `01_문장구조.md` 6장의 방식으로 텍스트로 쓴다. 정의된 5개 섹션은 3장 세트, 그 밖은 3.6절 일반형.

소항목이 없는 대항목은 `#` 아래 바로 블록을 쓴다. 소항목 번호는 양식 표기 그대로(`## (1) 개발 내용`도 됨). 정량 목표는 양식에 성능지표 표가 있으면 그 칸을, 없으면 블록 안에 `① 지표: 현재 → 목표 (측정 방법)` 줄로.

쓴 뒤 `lint_text.py 05_본문/ --limit <양식 분량>`. 지적 사항은 스스로 고친다. 키워드 반복은 `audit_keywords.py 05_본문/ --keywords A,B,C`로 — 파일 축이라 자가진단·안전보안 같은 행정 파일은 자동 제외된다.

## 8. 병합 → `06_최종.md`

`assets/최종산출물_포맷.md`의 고정 구조:

1. `# 전략 검토` — `## 핵심 키워드`(서술식 3문단) / `## 전략 매트릭스`(04_정렬 표 그대로) / `## 유지할 점 / 수정할 점`
2. 본문 — 양식 목차 순서로 `05_본문/*.md` 병합
3. `# 준비할 입증 자료` — 우선순위 목록. 본문의 `(입증 자료 필요)`·`(준비 필요)`를 모아 정리
3-1. `# 확인할 규정` — 본문의 `` `[기준]` `` 을 모아 정리. **`[기준]` 이 하나라도 있으면 반드시 만든다.**
   입증 자료와 성격이 다르다 — 우리가 만들 것이 아니라 **찾아 읽을 것**이다
**병합 뒤 마지막으로 한 번 더 본다.**

```bash
python3 scripts/audit_keywords.py 06_최종.md --keywords A,B,C --h1
```

`--h1` 은 `#` 대항목만 본다. 매트릭스가 대항목 축이므로 소항목마다 키워드 3개를 요구하면 과하다.
여기서 뜨는 누락은 **매트릭스의 `세로 검토` 판정과 일치해야 한다.** 어긋나면 둘 중 하나가 틀렸다.

4. `# 심사표 대조` — 배점 항목별 강·약. 배점은 **① 별도 심사표 파일 → ② 공고문 본문(`find_rubric.py`) → ③ 기본값** 순으로 찾는다.
   ①②로 찾았으면 `[기본값]` 표시를 붙이지 않는다 — 실제 공고 기준이라는 뜻이다.
   **셋 다 없어도 비우지 않는다.** 아래 기본 배점표를 `[기본값]` 표시와 함께 넣고 강·약 칸은 비운 채,
   "공고문의 심사표를 함께 주시면 실제 배점으로 대조해 드립니다" 한 줄을 붙인다.
   `기술성 40 · 사업성 20 · 기술개발역량 20 · 파급효과 15 · 자금집행계획 5`

전달할 때: **준비할 입증 자료 목록**을 채팅에 요약하고, "사업계획서실무교재.html에 06_최종.md를 끌어다 놓으면 전략 검토와 사업계획서 본문을 볼 수 있고, 고친 뒤 **전체 MD 복사**를 눌러 채팅에 붙여 주시면 다듬어 드립니다"를 안내한다.

## 9. 다듬기

사용자가 교재에서 고쳐 저장한 `06_최종.md`를 받는다. 교재는 고친 항목의 헤딩 바로 아래에 `<!-- 수정됨 -->`을 넣는다(`##` 소항목, 또는 소항목이 없는 `#` 대항목 — 그 경우 다음 `#`까지가 범위). 안 고친 항목은 원문 그대로다.

1. `<!-- 수정됨 -->` 항목만 손댄다. 표시가 없으면 이전 `06_최종.md`와 비교해 바뀐 줄을 찾는다
2. 사용자가 바꾼 내용은 **의미를 유지**한다. 맞추는 것은 문장 규칙뿐 — 3분할·2분할·말머리·명사형 종결·금지어, 그리고 위치(입증 방안 줄은 블록 끝, 세부 줄은 상위 메시지 아래)
   - 사용자가 **넣은 수치·사실**은 기업정보와 같은 지위. 그대로 쓴다. 옆의 `(측정 필요)`는 사용자가 실측이라 하면 지우고, 추정이면 `(추정)`으로 바꾼다. 같은 지표를 가리키는 다른 곳의 `(측정 필요)`도 — 수정됨 밖이라도 — 그 토큰만 함께 갱신하고 보고에 적는다
   - 사용자가 **지운 줄**은 복구하지 않는다. 그래서 블록에 필수 역할(개발 대상 등)이 빠지면 보고에 한 줄 적는다
   - 말머리 세트에 없는 역할의 줄이면 다른 섹션 말머리를 빌린다(개발내용 안의 현황 줄 → `(현 상황 한계)`). 빌릴 것도 없으면 그 줄의 역할을 2~4자로 새로 만든다(`(시범 대상)`)
   - `(아직 미정)` 같은 사용자 메모는 `(확인 필요: 학교명)`으로 정규화하고 `# 준비할 입증 자료` 끝에 추가한다
   - 볼드·표 기호는 벗겨져 있다. 표 여부는 이전 `06_최종.md`나 `02_이해.md` 양식 지침 칸으로 판단해 복원한다
3. 안 건드린 항목은 그대로 둔다. 전략 검토는 손대지 않는다 — 단, 사용자 수정으로 상위 메시지의 `(#키워드)`가 빠지거나 바뀌었으면 `수정할 점`에 한 줄 추가한다
4. `<!-- 수정됨 -->` 표시를 지우고 `lint_text.py` 재실행. 말머리를 붙인 뒤 다시 한 번 돌린다(말머리 없는 줄은 첫 실행에서 나머지 규칙이 가려질 수 있다)
5. 저장하고, **바꾼 줄 목록**(전 → 후)을 보고한다

사용자가 특정 항목만 지목하면("2-1만 더 구체적으로") 그 항목만 다시 쓴다.

**키워드가 바뀌었으면 본문을 전수 동기화한다.** 사용자가 전략 매트릭스의 셀이나 키워드를 고쳐 오는 경우가 있다.
매트릭스만 고치고 본문을 두면 세로 흐름이 끊긴다.

1. `audit_keywords.py 05_본문/ --keywords <새 키워드 3개>` 로 어느 목차에서 빠졌는지 확인
2. 빠진 목차의 상위 메시지 `(#키워드)` 를 새 키워드로 바꾸고, 그 키워드로 풀 수 있게 문장을 고친다
3. 매트릭스의 `세로 검토` 문구를 새 관통 논리로 다시 쓴다
4. 바꾼 목차 목록을 보고에 적는다

키워드를 **아예 새로 뽑자**고 하면 3단계로 돌아가 확정 요약부터 다시 한다 — 뒤가 전부 바뀌기 때문.
