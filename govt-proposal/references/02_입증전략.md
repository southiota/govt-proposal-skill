# 입증 전략

문장이 좋다고 믿지 않는다. 심사자는 **기술·인력·경험·납품 이력 같은 현실 자산**을 본다. LLM 텍스트와 현실 사이 간극은 기업정보와 리서치가 좁힌다. "보이기 좋게 꾸미는 것"(인지전략: 키워드·구성·반복)과 "자료로 입증하는 것"(입증전략: 특허·실적·확인서)을 나눠 고민한다.

## 1. 항목별 입증 매핑

| 항목 | 입증 방안 |
|---|---|
| 배경·필요성 | 정부 정책, 기관 리포트, 통계, 현장 설문 |
| 개발내용 | 인력, 컨소시엄, 상세 방안, 프로토타입/POC 화면 |
| 개발 목표 | 표준·공인 인증, 실증/테스트베드 참여 의향서 |
| 사업화 | 실증 협약서, 구매의향서, MOU, 기존 채널, 추정 손익 |
| 선행연구 | 특허, 논문, 노하우, 기존 개발 실적 |
| 팀·추진체계 | 참여 기관 정보, 협약서, 대표자·책임자 경력 |
| 추진일정 | 리스크 대응 시각화 (상호 의존 블록, 다중 트랙) |
| 사업비 | 행정 경험 인력 배치, 사업비 처리 사전 검토 |

## 2. 합격 사례 원칙 (『정부지원사업 합격의 정석』)

- 구매의향서는 분량 제한 무시하고 최대한 많이. 직인·사인이 있어야 믿는다
- 해외 판매처·진출 실적은 사소해도 증빙(지재권·MOU·계약·수출확인서) 첨부
- AS-IS/TO-BE 구성도를 앞부분에. 차별점·선행연구는 이미지 있는 표 1페이지로
- 테스트 장면 단계별 캡처, 알고리즘은 개발 단계별 코딩 캡처, O2O는 실제 현장 사진
- 출원과 등록은 다르다 — 등록 특허가 훨씬 유리. 없으면 출원부터
- 효과는 수치로(pH5+, 30초 건조). 검증은 의사·교수 공동연구로. 성능지표는 검증방법까지
- 목표매출은 개발완료 후 최소 5개년 + 산출근거. `0,000천 원` 지양
- 협력업체는 많을수록 좋다 — 프리랜서·전문가도. 협력 부분 명시. 대표자 경력은 겸손 없이
- 사회적 문제·약자 해결 아이템은 선정 가능성 높음. 베타테스트·설문 결과는 첫 페이지에
- 창업아이템 개요는 양식 1페이지 무시하고 3페이지 — 가장 중요한 부분
- 선투자 비용이 크면 진정성으로 읽힌다

## 3. 자료가 없을 때의 대안

| 입증하려는 것 | 대안 |
|---|---|
| 시장 수요 | 현장 설문, 검색량 추이, 커뮤니티 게시글 수, 기사 지면 |
| 정책 부합 | 정부 로드맵 문구 직접 인용, 부처 발표, 법·제도 조항 |
| 기술 가능성 | 논문 재현, 오픈소스 벤치마크, 유사 사례 성능 |
| 수요처 | 협의 이력, 이메일 회신, 담당자 호응 |
| 팀 역량 | 자문 전문가 참여, 과거 결과물, 학회 발표 |
| 실증 환경 | 대학·병원·지자체 MOU, 테스트베드 의향서 |

기업정보에 없는 실적·수치·거래처는 **사실인 척 쓰지 않는다.** 그렇다고 빈칸으로 두지도 않는다 — 사용자는 빈칸을 그대로 제출한다.

`` `[예시]` `` 표시를 붙여 **형식이 보이게** 채우고, 같은 항목을 `# 준비할 입증 자료`에 올린다. 이 짝이 목록의 재료다.

- `` `[예시]` 62% `` — 실측 전 수치. 무엇을 어떻게 재야 하는지 측정 방법을 함께 적는다
- `` `[예시]` 김OO / 공학박사 `` — 인사 기록에서 바꿀 자리
- `(입증 자료 필요: 구매의향서 2~3건)` — 값 자체를 예시로 만들 수 없는 첨부물

표시가 붙지 않은 값은 사실이라는 뜻이다. 사실이 아닌데 표시를 빼는 것이 이 스킬에서 가장 큰 사고다.

## 4. 심사 대응 — 기술 논쟁을 피한다

> "위상 최적화로 경량화가 어떻게 가능한가요?"
> ❌ "00 기술로 00을 적용해서…" → 논쟁, 불신
> ⭕ "00 방법으로 합니다. **00연구에서 00한 사례가 있습니다.**" → 사례·인력·컨소시엄으로 대응

개발 내용은 What·How·Goal + 핵심 전략(인력·방법론·네트워크) 위주로. 세부 방법은 추진 중 바뀌므로 큰 틀로. 사업화는 "매출을 올리겠다" 대신 확보된 수요(계약·협약)를 보인다.
