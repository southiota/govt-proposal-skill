# 셀프 인터뷰

**인터뷰의 목적은 테마를 정하는 것이다.** 무엇을 할 것인가가 서기 전에는 계획서를 쓸 수 없다.
공고문도 양식도 심사표도 "이 주제로 간다"가 정해진 다음에야 쓸모가 생긴다.

## 순서

```
1. 아이디어 여부를 묻는다   있는지 없는지부터. 자료를 다 읽은 뒤여도 이 질문부터
2. 인터뷰한다               있으면 구체화(A) · 없으면 발굴(B). 한 번에 한 문항씩
3. 테마를 확정한다          문제·키워드 3개·과제명을 정리해 "이 주제로 갈까요?" 확인
4. 세부를 묻는다            목표 · 입증 자산 · 파트너 · 범위
```

**테마는 인터뷰의 결과이지 전제가 아니다.** 1·2 를 건너뛰고 3부터 시작하지 않는다.
자료를 보고 테마를 지어 "이걸로 갈까요?"부터 묻는 것은 1·2 를 건너뛴 것이다.

인터뷰가 끝나면 이후 단계(이해→구조화→정렬→본문→병합)는 **확인 없이 자동으로** 진행된다.
그래서 인터뷰는 뒤 단계가 필요로 하는 입력을 **전부** 확보해야 한다. 여기서 놓친 것은 뒤에서 지어내거나 빈칸이 된다.

## 두 단으로 나눠 진행한다

| 단 | 무엇을 하는가 | 끝나는 조건 |
|---|---|---|
| **1부 · 아이디어 → 인터뷰 → 테마 확정** | 무슨 문제를 무엇으로 풀지 **찾아 간다** | 문제·키워드 3개·과제명에 사람이 동의 |
| **2부 · 세부** | 그 테마를 어떻게 입증할 것인가 | 체크리스트 4~9 가 채워짐 |

**1부가 끝나기 전에 2부를 묻지 않는다.** 테마가 바뀌면 정량 목표도 입증 자산도 파트너도 전부 바뀐다.
테마가 서지 않았는데 지표부터 묻는 것은 순서가 뒤집힌 것이다.

1부 끝(위 순서의 3)에서 한 번 되짚는다 — **"이 주제로 가겠습니다. 맞습니까?"**
이건 승인이 아니라 방향 확인이다. 아니라고 하면 인터뷰로 돌아간다.

## 인터뷰는 건너뛸 수 없다

**자료가 아무리 충실해도 인터뷰를 생략하지 않는다.**
공고문·기업정보는 **보기를 만드는 재료**이지, 답이 아니다.
자료에서 답을 추론해 체크리스트를 혼자 채우고 요약만 보여주는 것은 인터뷰가 아니다.

- **아이디어는 사람이 정한다.** 기업정보에 특허·실적·기술이 다 있어도, 그중 무엇으로 어떤 문제를
  풀지는 대표가 정할 일이다. 자료로 후보를 만들어 **고르게** 한다
- **키워드 3개도 사람이 고른다.** 계획서 전체를 관통하는 축이라 여기서 틀리면 전부 다시 쓴다
- **묻는 것과 승인받는 것은 다르다.** 질문은 여러 번 하고, 승인은 마지막 확정 요약에서 한 번만 받는다.
  "유일한 확인 지점"은 **승인**이 한 번이라는 뜻이지 대화가 한 번이라는 뜻이 아니다

**첫 질문은 언제나 "구상하신 아이디어가 있으신가요?" 다.** 자료를 읽었더라도 이 질문부터 한다.
답을 듣기 전에는 과제명·키워드·정량 목표를 쓰지 않는다.

## 진행 규칙

- 한 번에 한 문항. 객관식 3~5개 + "직접 입력"을 항상 연다. **묻고 나서 답을 기다린다**
- 공고문·기업정보를 먼저 읽고, 그 안의 구체적 표현을 보기에 넣는다
- 답이 얕으면 각도를 바꿔 한 번 더 파고든다. 특히 **수치**가 나오면 붙잡는다 — 그게 개발 목표가 된다
- 페르소나: **"엔지니어 출신 기자"** — 기술적 실현 가능성과 시장성을 집요하게

## 확보해야 할 것 (체크리스트)

인터뷰 종료 조건이다. 하나라도 비면 그 항목을 묻는다.
**1~3 은 1부에서 문답으로 찾아 가는 것이고, 4~9 는 테마가 확정된 뒤 2부에서 묻는다.**

| # | 단 | 항목 | 없으면 뒤에서 생기는 일 |
|---|---|---|---|
| 1 | 테마 | 해결할 문제 / 핵심 개발 내용 / 수요처 | 배경·목적·사업화의 재료 |
| 2 | 테마 | **키워드 3개** + 선정 이유 + 기업역량 연결 | 전 단계의 축. 가장 중요 |
| 3 | 테마 | 과제명(가안) — 3단 구조 | 매트릭스 축이 흔들림 |
| 4 | 세부 | 정량 목표 후보 2개 이상 (현재 수준 → 목표) | 성능지표표가 빈칸 |
| 5 | 세부 | 보유 입증 자산 체크 — 특허·논문·납품·MOU·인력·시설 | 입증 전략이 전부 "제안"에 머묾 |
| 6 | 세부 | 미보유 자산 중 접수 전 확보 가능한 것 | 준비 목록이 안 나옴 |
| 7 | 세부 | 공모 유형 (지정/자유) + RFP 요구 항목 | 구조화 방식 결정 |
| 8 | 세부 | 참여기관·위탁·수요기업 여부 | 추진 체계 섹션이 빈칸 |
| 9 | 세부 | 개발 기간·범위 (어디까지가 성공인가) | 일정·목표 과장 |

**1 → 2 → 3 순서다.** 문제가 정해져야 키워드가 나오고, 키워드가 서야 과제명이 3단으로 써진다.
거꾸로 과제명부터 지어내면 나머지를 거기에 억지로 맞추게 된다.

## 1부 — ① 아이디어 여부 · ② 인터뷰 · ③ 테마 확정

### ① 아이디어 여부 — 트랙 분기

첫 질문은 이것으로 고정한다. 자료를 다 읽은 뒤여도 마찬가지다.

> 구상하신 아이디어가 있으신가요?
> 1. 있다 — 무엇인지 말씀해 주세요
> 2. 어렴풋하다 — 방향만 있고 구체적이지 않다
> 3. 없다 — 기업정보와 공고문을 보고 함께 찾고 싶다
> 4. 직접 입력

**2번은 A 트랙으로 가되 재정의안을 먼저 보여주고, 3번은 B 트랙으로 간다.**
자료로 후보를 만들어 제시하는 것은 되지만, **고르는 것은 사람이다.**

### ② 인터뷰 · A — 아이디어 있음 → 구체화

문제는 완성도가 아니라 **공고문과의 간극**이다.
아래 1~3 이 1부다. 4~7 은 테마가 확정된 뒤 2부에서 묻는다.

1. **정부 시선 먼저** — 질문 전에 공고문에서 정리해 보여준다: 이 공고가 해결하려는 문제 / 지원 분야 / 정책 키워드 / 평가에서 볼 것
2. **간극 진단** (2~3문항)
   - 지원분야 정합: 공고의 실제 분야 목록 중 어디인가 / 애매하다
   - 기술 단계: 아이디어만 / 설계 완료 / 시제품 / 일부 매출
   - 차별점: 성능 / 비용 / 속도 / 적용범위 / 접근성
3. **재정의안 2~3개** — 정책 정렬형 / 역량 정렬형 / 절충형. 근거와 트레이드오프를 붙여 고르게 한다. "같은 아이디어를 공고의 언어로 다시 쓰는 것"임을 분명히
4. **정량 목표** — "지금 얼마이고, 끝나면 얼마가 되나요?" 최소 2개. 모르면 `(측정 필요)`
5. **입증 자산 체크** — 기업정보를 표로 보여주고 있음/없음/준비 중 확인. 없는 것 중 접수 전 확보 가능한 것 표시
6. **파트너** — 참여기관·위탁·수요기업·실증 장소. 없으면 "필요한가"
7. **범위** — 기간 안에 어디까지. 시제품 / 실증 / 양산

### ② 인터뷰 · B — 아이디어 없음 → 발굴

자산 → 문제 → 크기 → 원인 → 정책 → 수요처 → 범위 → 경쟁 → 성공 기준 → 파트너. 10문항.
**1~6 이 ② 인터뷰이고, 7~10 은 2부다.** 6번에서 수요처가 나오면 재료가 다 모인 것이니 ③ 으로 넘어간다.

| # | 질문 | 보기 예 |
|---|---|---|
| 1 | 회사가 가장 자신 있는 게 뭔가요? | 기술·알고리즘 / 설비 / 고객 네트워크 / 현장 경험 / 데이터 |
| 2 | 그 일을 하며 "이건 이상한데" 싶었던 순간은? | 사람이 계속 붙어야 함 / 자꾸 틀리는 판단 / 비싼 공정 / 안 쓰이는 데이터 / 위험 작업 |
| 3 | 그 문제로 연간 얼마나 손해를 보나요? | 인건비 / 불량·폐기 / 다운타임 / 사고 리스크 / 수주 실패 — **숫자를 묻는다** |
| 4 | 왜 지금까지 안 풀렸나요? | 기술이 없어서 / 너무 비싸서 / 현장이 특수해서 / 데이터가 없어서 / 관심이 없어서 |
| 5 | 이 문제를 정부 언어로 옮기면? | **공고문에서 뽑은 키워드 3~5개** + "모르겠다" (고르면 후보와 근거 제시) |
| 6 | 해결하면 누가 먼저 돈을 내나요? | 자사 원가절감 / 기존 고객 / 동종 타사 / 공공·지자체 / 신시장 |
| 7 | 기간 안에 어디까지 만들면 성공인가요? | 알고리즘 검증 / 시제품 / 현장 실증 / 양산 |
| 8 | 지금 비슷한 걸 하는 곳이 있나요? 무엇이 다른가요? | 국내 경쟁사 / 해외 / 대체 방식 / 없음 |
| 9 | 성공했다고 판정할 숫자는? | 정확도 / 시간 / 비용 / 불량률 — **현재 → 목표** |
| 10 | 함께할 곳이 있나요? | 대학 / 연구소 / 수요기업 / 없음 |

**확인할 것**: 본인 회사만의 문제인가, 산업 공통 문제인가 (후자여야 과제가 된다). 보유 자산과 개발 내용의 거리 (너무 멀면 선행연구를 못 채운다).

### ③ 테마 확정

문답에서 나온 것을 모아 **문제 → 키워드 3개 → 과제명(가안)** 순으로 정리해 보여주고 묻는다.

> 이 주제로 가겠습니다. 맞습니까?
> 1. 맞다 — 세부로 넘어가자
> 2. 키워드를 바꾸고 싶다
> 3. 주제 자체를 다시 보고 싶다
> 4. 직접 입력

2·3 이면 ② 로 돌아간다. 1 이어야 2부로 넘어간다.
과제명은 `01_문장구조.md` 2장의 3단 구조로 쓴다.

### 정부 중점 방향 키워드 풀 (5번 문항 보기용)

공고문 키워드를 우선하고, 없을 때 참고한다. 유행하는 단어가 아니라 **방향이 같은 단어**여야 한다.

AI·데이터: 피지컬 AI, AI 융합, AX, 온디바이스 AI, 제조 AI · 제조: 스마트팩토리, 공정 자율화, 디지털 트윈, 예지보전 · 안전·노동: 중대재해처벌법, 휴먼에러, 산업안전, 인력 부족 · 환경: 탄소중립, 순환경제, 에너지 효율 · 공급망: 소부장 국산화, 수입 대체, 기술 자립 · 사회: 초고령사회, 지역소멸, 돌봄, 사회적 약자 · 모빌리티: 자율주행, 전동화, 물류 자동화 · 바이오: 디지털 헬스케어, 정밀의료

## 2부 · 세부

테마가 확정된 뒤에만 묻는다. 정량 목표 → 입증 자산 → 접수 전 확보 가능 → 공모 유형 → 파트너 → 범위.
확정된 테마를 기준으로 물어야 답이 구체적으로 나온다.

## 확정 요약 → `01_아이디어.md`

**대화로** 체크리스트 9개를 채운 뒤 아래 형식으로 정리해 보여주고 **"이대로 진행할까요?"** 한 번 묻는다.
승인은 여기 한 번뿐이다 — 그러나 **여기까지 오는 길은 여러 번의 문답이어야 한다.**
질문 없이 이 요약부터 내놓았다면 인터뷰를 하지 않은 것이다.

```markdown
# 아이디어

## 과제
- 과제명(가안):
- 공모 유형: 지정 / 자유   (지정이면 RFP 요구 항목 번호 목록)
- 해결할 문제:
- 핵심 개발 내용:
- 수요처:
- 개발 범위·기간:

## 핵심 키워드 3개
| 키워드 | 선정 이유 (공고문·정책 근거) | 기업역량 연결 |
|---|---|---|

## 정량 목표 후보
| 지표 | 현재 | 목표 | 측정 방법 |
|---|---|---|---|

## 입증 자산
| 자산 | 보유 | 접수 전 확보 가능 |
|---|---|---|
| 특허 (등록/출원) | | |
| 논문·학회 | | |
| 납품·매출 실적 | | |
| MOU·구매의향서·실증 협약 | | |
| 인력 (책임자 경력) | | |
| 시설·장비 | | |

## 파트너
- 참여기관 / 위탁 / 수요기업 / 실증 장소:

## 인터뷰에서 확보한 수치
- (그대로 옮긴다 — 개발 목표와 배경 근거가 된다)
```

키워드는 ③ 에서 **"이 세 단어로 계획서 전체를 관통시킬 텐데 맞나요?"**를 명확히 묻는다.
