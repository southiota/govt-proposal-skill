# 형식 항목 — 규정이 형식을 정하는 곳

계획서의 항목은 세 수준으로 갈린다. **수준이 다르면 쓰는 방법도 다르다.**

| 수준 | 무엇 | 어떻게 | 어디 |
|---|---|---|---|
| **1수준** | 배경·목적·개발내용·선행연구·사업화 | 전략에 따라 문장을 만든다. 3분할 상위 메시지 + 2분할 세부 | `01_문장구조.md` 3장 |
| **2수준** | 요약·정량 목표·기대효과처럼 **값이 필요한 곳** | 형식을 보이고 `` `[예시]` `` 로 표시. 사용자가 실측·조사로 교체 | `01_문장구조.md` 6장 |
| **3수준** | 사업비·일정·인력·컨소시엄·발표자료 | **규정이 형식을 정한다.** 임의로 만들지 않는다 | 이 문서 |

3수준을 1·2수준처럼 쓰면 형식은 그럴듯한데 **규정 위반**이 된다.
사업비 비목을 잘못 쓰면 반려되고, 참여율이 상한을 넘으면 협약 단계에서 걸린다.

## `[기준]` 표기

3수준에는 표기가 하나 더 붙는다.

| 표기 | 뜻 | 누가 채우나 |
|---|---|---|
| `` `[예시]` `` | 형식을 보여주는 값 | **측정·조사하면 나온다.** 사용자가 실제 값으로 교체 |
| `` `[기준]` `` | **규정·공고가 정하는 값** | 지어내면 안 된다. 공고문·사업비 산정기준·협약 규정 **원문을 확인**해서 채운다 |
| 표기 없음 | 사실 | 기업정보·공고문에서 그대로 가져온 것 |

`[기준]` 은 `# 준비할 입증 자료` 가 아니라 **`# 확인할 규정`** 목록으로 모은다. 성격이 다르다 —
입증 자료는 우리가 만들어야 할 것이고, 규정은 우리가 찾아 읽어야 할 것이다.

```markdown
# 확인할 규정

1. **사업비 비목 체계와 계상 기준** — 공고문 「사업비」 절 · 사업비 산정기준 고시
2. **대응자금(민간부담금) 비율과 현물 인정 범위** — 공고문
3. **참여연구원 참여율 상한과 겸직 제한** — 국가연구개발혁신법 시행령
```

---

## 1. 사업비

**임의로 금액을 정하지 않는다.** 순서가 있다.

1. 공고문의 **지원한도·지원비율·대응자금 비율**을 찾는다 (`find_rubric.py` 로 못 찾으면 직접)
2. 그 사업의 **비목 체계**를 확인한다. 사업마다 다르다
3. 비목별로 산출 근거를 세운다 — **금액보다 근거가 배점을 가른다**

```
1. (#키워드) 인력 중심 개발 구조에 따른 인건비 우선 배정 및 비목 최소 구성
  - (인건비) `[예시]` 정부 96,000 / 민간 24,000천 원 — 참여연구원 6명 × 참여율 × 12개월
  - (연구장비·재료비) `[예시]` 정부 38,000 / 민간 6,000천 원 — 실증용 단말 20대, 시험 보드
  - (간접비) `[기준]` 고시 비율 적용 — 기관 유형별 요율은 사업비 산정기준 확인
  - (대응자금 비율) `[기준]` 공고문 확인 — 현금·현물 인정 범위 포함
  (입증 방안: 비목별 산출 근거표 — 준비 필요, 사업비 처리 사전 검토)
```

**엄격 기준 항목** — 아래는 `[기준]` 을 붙인다. 추측하면 반려 사유가 된다.

- 간접비 요율 · 인건비 계상 기준(현금/현물) · 대응자금 비율
- 장비 구입 한도와 감가상각 · 위탁연구개발비 상한
- 사업비 변경 승인 절차

## 2. 추진일정

연차·단계 구분은 **공고가 정한 개발기간**을 따른다. 임의로 늘리거나 줄이지 않는다.

```
1. (#키워드) 총 12개월 단일 연차 구성 기반 설계·개발·실증 3단계 분할 및 학기 일정 연동
  - (설계) 1~3개월 현행 구조 분석 및 이식 범위 확정 — 산출물: 범위 정의서
  - (개발) 4~9개월 모듈 개발 및 중간 검증 — 산출물: 전후 대조 결과
  - (실증) 10~12개월 현장 측정 및 보완 — 산출물: 완주율 보고서
  - (개발기간) `[기준]` 공고문 확인 — 최대 기간과 연차 구분 방식
```

**엄격 기준 항목** — 개발기간 상한 · 연차 구분 방식 · 단계평가(연차평가) 시점.

## 3. 참여인력

인원 수보다 **참여율과 자격**이 규정 대상이다.

```
1. (#키워드) 직원 N명 중 개발 인력 배치를 통한 단독 수행 체계 구성 및 항목별 책임 확정
  - (총괄) `[예시]` 김OO, 대표이사, 공학석사·전자공학 — 과제 총괄 및 실증 협의
  - (설계) `[예시]` 이OO, 연구소장, 공학박사·로봇공학 — 추론 구조 설계 총괄
  - (참여율) `[기준]` 규정 확인 — 1인 총 참여율 상한과 타 과제 겸직 제한
  - (연구책임자 자격) `[기준]` 공고문 확인 — 학위·경력 요건 유무
  (입증 방안: 경력기술서 — 준비 필요, 4대보험 가입 증빙)
```

**엄격 기준 항목** — 1인 총 참여율 상한 · 겸직 제한 · 연구책임자 자격 요건 · 청년 의무채용 비율.

## 4. 컨소시엄·추진체계

원자료의 팀 구조를 계획서 항목으로 옮긴 것이다. 참여기관이 있을 때만 쓴다.

| 역할 | 담당 | 주요 활동 |
|---|---|---|
| **#전략** — 계획서 밖 수주 전략 | 정책관리 · 컨소시엄관리 | 정책 정렬 명분 발굴, 약점을 메울 파트너 구성 |
| **#전달** — 문서의 제안 전략 | 총괄 PM · 품질관리 | 핵심 메시지 결정, 스토리텔링을 문서에 구현 |
| **#내용** — 구체적 내용의 완성 | 기술관리 · 사업관리 | 개발 방법·정량 목표·평가 방법론, 행정 서류와 사업비 |

```
1. (#키워드) 약점 보완형 컨소시엄 구성을 통한 수행 신뢰도 확보 및 역할 분담 확정
  - (주관기관) ㈜OO — 개발 총괄 및 실증 운영. 보유 특허 2건으로 기술 기반 담당
  - (참여기관) `[예시]` OO대학교 — 경량화 성능 외부 교차 검증. 우리가 못 하는 것을 맡는다
  - (역할 중복) 주관과 참여의 담당 항목이 겹치지 않도록 분리 — 겹치면 감점
  - (기관 자격) `[기준]` 공고문 확인 — 참여기관 유형별 자격과 지분 요건
  (입증 방안: 컨소시엄 협약서 — 준비 필요, 참여기관 사업자등록증)
```

**WBS 는 조직도가 아니라 일이 쪼개진 그림이다.** 개발 항목 → 세부 과업 → 담당 기관 순으로 적고,
기관 간 인수인계 지점을 명시한다. 그 지점이 곧 리스크다.

**엄격 기준 항목** — 참여기관 자격 · 기관별 사업비 지분 한도 · 위탁연구 비율 상한.

## 5. 발표자료

**발표는 계획서 순서를 따르지 않아도 된다**(원자료 2.3). 설득력이 올라간다면 순서를 바꾼다.

| 계획서 순서 | 전략화된 발표 순서 |
|---|---|
| 배경 → 개발내용 → … → 사업비 → 기대효과 | 현황으로 **공감 형성** → 문제 발굴·대응전략 → 개발내용 → … → 사업비 → **가치제안** → **사업포부** |

매트릭스 위아래에 INTRO·OUTRO를 붙인 것이 발표 골격이다.

- **INTRO** — "왜 지금 이 연구가 필요한가"로 공감. 배경 키워드 3개를 한 장면으로
- **본문** — 매트릭스를 세로로 읽은 순서. 키워드마다 한 줄기
- **OUTRO** — 이 연구가 가져올 가치. 계획서에는 없어도 발표에는 넣는다

**가정을 세워 설계한다.** 평가 기업이 많고 발표 순서가 후반부면 평가자 피로가 크다.
핵심 결정자가 기술을 모를 수도 있다. 그런 경우 인·아웃트로에 **의의·명분을 강화**하고
기술 내용에 힘을 뺀다. 기술로 답하면 논쟁이 되고, 사례로 답해야 신뢰가 된다(`02_입증전략.md` 4장).

**엄격 기준 항목** — 발표 시간 · 장표 수 제한 · 제출 형식(PPT/PDF)·마감. 공고문에서 확인한다.

## 언제 이 문서를 읽나

7단계에서 양식 목차에 **사업비·일정·인력·추진체계·컨소시엄** 항목이 있을 때.
발표자료는 사용자가 요청할 때만.

3수준 항목에도 문장 규칙은 그대로다 — 상위 메시지 3분할, 세부 2분할 또는 `(말머리) 값 — 근거`.
다른 것은 **값의 출처**뿐이다.
